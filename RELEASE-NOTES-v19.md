# Сириус — усиление безопасности v19

## Реализовано в коде

- Добавлен отдельный серверный предел: не более 30 одновременно открытых SSE-подключений с одного IP-адреса.
- Лимит проверяется на endpoint `/api/stream` после проверки одноразового билета и актуальности сессии. Он дополняет прежние ограничения: максимум 6 потоков на аккаунт и 5000 потоков глобально.
- В объект активного SSE-клиента записывается IP, полученный серверной функцией `ipOf`; заголовки прокси учитываются только при настройке доверенного прокси, как и в остальной части сервера.
- Добавлен интеграционный регрессионный тест: создаёт шесть тестовых аккаунтов, открывает 30 потоков с одного IP и проверяет, что 31-й получает HTTP 429.
- Новый тест включён в `npm test`.

## Проверка

- `node --check server.js` — успешно.
- `node --check security-sse-ip-limit-test.js` — успешно.
- `npm test` — все 21 проверки/сценария завершились успешно, включая новый тест ограничения SSE по IP.

## Влияние и ограничения

Это усложняет исчерпание ресурсов большим числом аккаунтов с одного IP. Лимит по IP может затронуть пользователей за общим NAT, поэтому значение 30 можно настроить после наблюдения за реальной нагрузкой. Это не исправляет ограничения E2EE и не является независимым аудитом безопасности.
