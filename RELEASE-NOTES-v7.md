# Sirius Security v7 — 19.10.2026

## Основные изменения для защиты пользователей

1. **Снижение перечисления аккаунтов при восстановлении.** Ответ на неизвестный username теперь использует тот же формат восьмизначного UID и соли, что и существующий аккаунт. Ошибка `rec/do` остаётся общей. Это снижает простой username enumeration, но не обещает устранить все временные/поведенческие каналы.
2. **Отзыв старых сессий после смены облачного пароля.** Сервер создаёт новый случайный 256-битный токен, заменяет его хэш в базе и закрывает текущие потоковые подключения/билеты. Клиент безопасно сохраняет новый токен и переподключается.
3. **Повторная аутентификация для удаления аккаунта.** Для необратимого удаления нужен корректный password-derived proof, подтверждённый сервером. Неверный пароль не удаляет профиль и медиа. Попытки ограничиваются; после успешной проверки удаляются связанные данные и файлы.
4. **Регрессионные тесты.** Проверяют формат восстановления, ротацию токена, отказ старого токена, отказ удаления без верного пароля и удаление медиа после подтверждённого удаления аккаунта.

## Проверки

- `node --check server.js`
- `node --check security-smoke-test.js`
- `node --check /tmp/sirius-inline.js` (inline script извлечён из `index.html`)
- `npm test` — все smoke-, E2E-envelope- и key-verification-тесты прошли.

## Важные ограничения

Это не независимый аудит и не основание автоматически выставлять 7/10. В проекте всё ещё нет полноценной проверенной реализации Double Ratchet/forward secrecy, passkeys/2FA, полного списка устройств и независимого penetration test. Активный XSS или компрометация устройства могут позволить злоумышленнику действовать от имени пользователя.
